---
title: Migrating from 0.x to 1.0
description: Step-by-step guide to migrating your cognito-local configuration from the 0.x single-pool schema to the 1.0 multi-pool schema.
---

cognito-local 1.0 introduces a multi-pool data model. The breaking change is the **config file shape** — your `users.json` and Docker setup don't need to change.

If you try to start cognito-local 1.0 with a 0.x-shaped config, it will refuse to boot with a clear error message pointing here.

## What changed

| 0.x | 1.0 |
| --- | --- |
| `userPoolId`, `userPoolName` at the top level | Each pool has its own `id` and `name` inside `pools[]` |
| `clients[]` at the top level | `clients[]` lives inside each pool |
| One pool per server | Any number of pools per server |
| No password policy | `passwordPolicy` per pool (defaulted) |
| No MFA config | `mfaConfiguration: "OFF" | "ON" | "OPTIONAL"` per pool |
| Implicit username-case insensitivity | `usernameCaseSensitive: boolean` per pool |
| Triggers not supported | Optional `triggers` block per pool |

## Migration recipe

### Before (0.x):

```json
{
  "region": "us-east-1",
  "userPoolId": "us-east-1_localDev01",
  "userPoolName": "cognito-local",
  "port": 9229,
  "clients": [
    {
      "clientId": "my-app-local",
      "clientSecret": "local-secret",
      "clientName": "My App",
      "callbackUrls": ["http://localhost:3000/callback"],
      "logoutUrls": ["http://localhost:3000"],
      "explicitAuthFlows": ["ALLOW_USER_PASSWORD_AUTH"],
      "allowedOAuthFlows": ["code"],
      "allowedOAuthScopes": ["openid", "email"]
    }
  ]
}
```

### After (1.0):

```json
{
  "region": "us-east-1",
  "port": 9229,
  "pools": [
    {
      "id": "us-east-1_localDev01",
      "name": "cognito-local",
      "usernameAttributes": ["email"],
      "usernameCaseSensitive": false,
      "autoVerifiedAttributes": ["email"],
      "mfaConfiguration": "OFF",
      "clients": [
        {
          "clientId": "my-app-local",
          "clientSecret": "local-secret",
          "clientName": "My App",
          "callbackUrls": ["http://localhost:3000/callback"],
          "logoutUrls": ["http://localhost:3000"],
          "explicitAuthFlows": ["ALLOW_USER_PASSWORD_AUTH"],
          "allowedOAuthFlows": ["code"],
          "allowedOAuthScopes": ["openid", "email"]
        }
      ]
    }
  ]
}
```

## Mechanical translation rules

1. Lift `userPoolId` → `pools[0].id`
2. Lift `userPoolName` → `pools[0].name`
3. Move `clients[]` inside `pools[0]`
4. Add the four new defaults to `pools[0]`:
   - `"usernameAttributes": ["email"]` if your users sign in with email
   - `"usernameCaseSensitive": false` (matches old behavior)
   - `"autoVerifiedAttributes": ["email"]`
   - `"mfaConfiguration": "OFF"`

That's it. `region` and `port` stay at the top level.

## Users file

`users.json` is unchanged. If you have multiple pools and want to assign a user to a specific pool, add `"poolId": "us-east-1_otherPool"` to the user entry. Users without a `poolId` are seeded into the first pool.

## Docker / env vars

`PORT`, `DATA_DIR`, `CONFIG_FILE`, `USERS_FILE` work the same. New env vars in 1.0:

- `COGNITO_LOCAL_DEVMODE=1` — log the request body of any unsupported SDK operation. Useful when integrating an SDK call that errors with `CognitoLocal#Unsupported`.
- `ISSUER_HOST` — overrides the issuer base URL (defaults to `http://localhost:${PORT}`). Useful for testcontainers / dynamic-port setups.
- `DEBUG=1` — sets log level to debug.

## Data directory

The on-disk JSON files (`pools.json`, `users.json`, `clients.json`, `refresh-tokens.json`, etc.) have new schemas in 1.0. **Delete your `temp-data/` directory before first 1.0 boot** to avoid mixing schemas.

## New features available after migration

- 50 additional SDK operations (full Cognito SDK parity)
- 9 Lambda trigger families (PreSignUp, PostConfirmation, PreTokenGeneration, etc.)
- TOTP-based MFA
- Groups with IAM-role / preferredRole support
- Custom attributes with required-field validation
- `client_credentials` OAuth2 grant
- ALB-style public-keys endpoint
- HTTPS server with self-signed certs
- Structured logging via pino
